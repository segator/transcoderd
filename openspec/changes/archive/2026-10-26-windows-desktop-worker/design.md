# Design

A Windows SCM service runs a headless supervisor under SYSTEM. The supervisor starts the existing worker binary and keeps an authenticated, SID-scoped local named pipe for the installing user and SYSTEM/administrators. An interactive tray shell hosts an HTML/CSS/JavaScript application in WebView2 in the logged-in user's session; Windows services do not own interactive desktops. The web content is bundled locally, has a restrictive content security policy, and talks to the service only through a narrow message bridge and local pipe. The SCM command line records the installer's SID so ordinary users cannot redirect the service's control ACL. The service stores configuration and the token under a SYSTEM/administrators-only ProgramData directory and returns only a token-present flag to the tray. Inputs are strictly validated before persistence or use as process arguments.

The worker's existing SYSTEM-scoped control pipe is used by the supervisor. Its status response gains thread-safe snapshots of active task progress and of accepted jobs waiting or running in each local pipeline phase, including whether the source is downloaded. The server additionally exposes a bounded, authenticated, read-only queue view, polled at a modest interval; older servers remain usable and are reported as not supporting the global view. Two internal operations drain admission locally without persisting a zero and request graceful process shutdown. The supervisor waits for both active jobs and reserved requests to drain before restarting for a changed server, credential, encoder or schedule. A limit-only change uses the existing persisted runtime limit. The service remains available for first-run configuration and retries a temporarily unavailable worker/server.

An NSIS installer includes the exact portable bundle, the service binary, the locally bundled web application and a self-contained tray shell using the WebView2 runtime. It registers the service, grants the installing SID access to the service pipe, adds a per-user login shortcut, and preserves ProgramData on uninstall. It refuses to replace the executable while work is active. Dagger builds cross-targeted binaries and an installer; hosted Windows executes native tests, installation/service integration and the existing CPU E2E before publication.

## Validation

Exercise progress snapshots and drain/shutdown locally and in Go tests. Test configuration validation and secret redaction, local pipe ACL, service lifecycle and GUI smoke tests on native Windows; test a real CPU worker against an isolated server. Validate upgrade/uninstall preservation and release packaging. Keep production workers stopped and do not install the production service on the user's PC without an explicit deployment request.
